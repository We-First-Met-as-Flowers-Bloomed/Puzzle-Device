# MaixCAM2 E 题拼图视觉

当前版本：`0.2.48`

白色自备碎片和白底扑克牌会先尝试经过数量、面积及 3～5 边形
规则验证的快速 Lab 分割；不满足条件的彩色碎片、低饱和度纸面或
复杂光照场景自动使用原有的自适应光照平面分割。

这套代码完成以下板端视觉链路：

1. 自动检测完整 A4 外轮廓并做透视校正；
2. 在 Lab 颜色空间检测规定的中部分界线；
3. 自动把有碎片的一侧旋转为纸面坐标的上半区；
4. 用纯色 A4 的背景模型分割 1–4 片直边碎片；
5. 提取多边形、质心和距离边界最远的稳定吸取点；
6. 先按边长、端点补角和直角/外边界先验建立候选图，枚举四片的全部全局连接树，再用 T 接点搜索补充；
7. 支持完整共边、长边内部偏移和一条长边被多片分段拼接的 T 接缝；
8. 自动区分纯色片与印刷片，只对扑克牌用跨接缝 Lab 颜色/梯度连续性消歧；
9. 把矩形居中放入 A4 下半区安全范围，输出每片吸取点、放置点和旋转量；
10. 可选地把 A4 毫米坐标映射为运动机构毫米坐标，并通过 UART 输出 JSON。

算法不需要网络、电脑端推理、AprilTag、额外定位线、补光或遮光板。比赛运行时只使用
MaixCAM2、板载 OpenCV/NumPy、A4 边界、规定分界线和碎片本身。

## 0.2.41 论文驱动的四条扑克牌重组

- 四个同宽矩形条带不再进入通用 C1/C2 几何搜索。新分支先把每条牌片校正到局部坐标，
  为每个方向建立有向相邻边代价矩阵，再组合整牌顺序；普通随机多边形、Figure-2 和纯色碎片路径不变。
- 接缝代价采用双向一阶边界预测与沿切口方向的梯度连续性，并允许 `±2 mm` 的只读采样偏移；
  绝对误差再按每条源边和目标边的四分位数归一化，避免空白白边天然压过真正的印花连续边。
- 把互为最近邻的接缝作为 `best-buddy` 可靠性证据，同时检查牌面两个角码是否位于对角。
  最终只需评估 `4!×2^4=384` 个由相邻边矩阵评分的整牌顺序；矩形几何只负责硬验收，不再主导牌面排序。
- 两张当前可用的 8♠ 现场原图均返回 `OK`：此前 `LOW_MARGIN` 的一张分差由 `0` 提高到约 `0.075`，
  另一张保持正确顺序且分差约 `0.105`；PC 检测加求解约 `0.9–1.8 s`，均为 384 个轻量顺序。
- 方法依据包括 Pomeranz 等人的预测兼容度与四分位归一化、Gallagher 的梯度兼容度、
  Son 等人的方向导数兼容度，以及条带碎纸重组的有向代价矩阵：
  [CVPR 2011](https://www.cs.bgu.ac.il/~ben-shahar/Publications/2011-Pomeranz_Shemesh_and_Ben_Shahar-A_Fully_Automated_Greedy_Square_Jigsaw_Puzzle_Solver.pdf)、
  [CVPR 2012](https://chenlab.ece.cornell.edu/people/Andy/Andy_files/Gallagher_cvpr2012_puzzleAssembly.pdf)、
  [CVPR 2016](https://openaccess.thecvf.com/content_cvpr_2016/html/Son_Solving_Small-Piece_Jigsaw_CVPR_2016_paper.html)、
  [CVPR 2020 论文与代码](https://github.com/thiagopx/deeprec-cvpr20)。
- 当前工作区可执行的 71 项视觉测试和 3 项标定测试全部通过；另有 10 项历史实拍测试因
  `tests/data` 图像未保留在当前工作区而无法执行。两张本轮现场原图已单独完成端到端回放。

## 0.2.38 四等分扑克牌整牌特征求解

- 新增四等分扑克牌识别：仅当四块均为近似矩形、面积比不超过 `1.18`、对应边长差不超过

- 中线不再只比较某一行的异色像素比例；现在联合使用距纸面 Lab 色差、相对暗度、细线局部对比、横向连续范围、线宽和几何中心先验。
- 支持手画黑线存在少量断笔和上下波动，并抑制长碎片边、宽阴影及远离纸张中点的伪直线；低置信度时安全回退到 A4 几何中点。
- 日志新增 `divider y=... mm, coverage=..., source=measured/center-fallback`，便于现场直接判断中线是否选对。
- 四片全局图的每条树边由 6 个候选降为 4 个，最坏状态数从 3456 降至 1024，为 MaixCAM2 的 T 接点搜索保留时间。
- 严格匹配 Figure-2 且填充、重叠、孔洞、边界、凸度、四角和尺寸均合格时，固定模板外边覆盖率允许到 `0.62`；通用现场碎片和扑克牌仍保持原有严格阈值。

## 0.2.8 同面全局配准图

- 所有碎片只允许平移和旋转，输出变换的行列式必须为正；铁片在背面的题目条件下不再把模板残差解释成“碎片翻面”，也绝不靠软件反射伪造解。
- 吸收图优化拼图算法的“冗余局部配准、全局组合裁决”思路：四片时枚举全部 16 棵标号生成树，每条树边保留 6 个 C1/C2 候选，最多检查 3456 个全局状态。
- 全局图阶段直接检查完整矩形的填充率、重叠、孔洞、四边覆盖、凸度、四角和尺寸；高置信解立即返回，其他合格解继续交给 T 接点路径择优。
- 固定 Figure-2 若只能闭合内部接缝、却不能形成严格矩形，会明确报告同面接点误差及 `fill/side/corner`，随后尝试通用求解；不会把非矩形结果标成成功。
- 扑克牌仍在全部几何合格候选之间用跨接缝纹理连续性消歧；纯色自备片不会承担这项开销。

## 0.2.6 Figure-2 双布局择优

- 每个 Figure-2 形状映射同时评估独立刚体布局和拼缝锁定布局；不再因为严格形状匹配成功而跳过更适合实物裁剪误差的布局。
- 两套布局都先通过完整矩形资格检查，再选择几何误差较小者；不会用放宽矩形阈值来掩盖拼接错误。
- 模板失败日志改为报告所有已检查布局中最接近矩形的候选，并标明 `independent` 或 `seam-locked`，不再显示容易误导的第一个候选。

## 0.2.5 Figure-2 外边覆盖容差

- 已确认 Figure-2 且其他矩形指标全部合格时，最差外边覆盖率下限
  使用 `0.75`；通用现场碎片和扑克牌仍使用配置中的 `0.88`。
- 覆盖本次板端日志的 `side=0.798`，同时继续拒绝低填充的非矩形
  实拍回归。

## 0.2.4 Figure-2 官方顶点容差快路

- 已确认是题图固定四片、且填充率、孔洞、重叠、四边覆盖、凸度、
  四角和尺寸全部合格时，碎片之间的小栅格缝隙按题目 20 mm
  对应顶点上限验收，不再误入板端通用搜索。
- 模板拒绝日志补充 `boundary=P95/P99` 和 `components`，以后不会再
  隐藏真正失败的条件。
- 低填充或明显非矩形的候选仍然拒绝；这一放宽不适用于比赛现场
  随机切法和扑克牌的通用求解。

## 0.2.2 快速通用求解与矩形资格审查

- 保留固定图 2 的快速模板路径；不匹配时自动进入通用求解，不再把所有切法硬套一个模板。
- 吸收双片优先、外轮廓链和矩形直角先验：从最可信的双片接缝开始，并按外边覆盖率和四角支持度排序。
- 双片种子按碎片对分桶保留，避免同一条错误接缝占满候选；四片任务额外尝试有界 `2+2` 双组拼接。
- 候选边图同时保留正反方向；处理 OpenCV 对“只接触、不重叠”的凸多边形误报。
- 长边除两端对齐外，还会从其他实测边长推导少量内部偏移，因此支持扑克牌和现场随机 T 接缝。
- 同一张牌的花纹只负责在几何合法解之间消歧，不会替代矩形、重叠、孔洞和边界检查。
- `texture_enabled=true` 为自动模式：纯色自备片跳过纹理开销，检测到数字/花色后才启用扑克牌路径。
- 所有求解路径统一检查填充率、重叠、孔洞、四边最小覆盖率、轮廓凸性、四角最大误差和边界 P95/P99；已确认的固定 Figure-2 只把栅格连通与边界误差改按官方 20 mm 对应顶点容差验收。
- 调试图顶部的 `side=` 是四条矩形边中最差一条的覆盖率，默认必须不低于 `0.88`。

## 坐标约定

- `paper_mm`：A4 校正坐标，原点为取料半区左上角，`x` 向右、`y` 向下，单位 mm。
- 代码会根据分界线和碎片自动消除相机画面中的 90°/180°摆放差异。
- `rotation_cw_deg`：从当前碎片姿态转到目标姿态的纸面顺时针旋转量，范围
  `[-180, 180)`。
- `pickup_paper_mm`：当前吸取位置。
- `place_paper_mm`：碎片旋转后，同一个吸取点应移动到的目标位置。吸嘴不在质心时也已经
  完成 XY 旋转补偿。
- `frame_to_robot`：把去畸变后的固定相机画面像素映射到龙门/机械臂毫米坐标的 3×3
  单应矩阵。程序会在线复合每次检测到的 A4 位姿，所以纸张在标定后发生平移或 90°/180°
  旋转时，机构坐标仍会同步更新。

运动控制应优先使用 `pickup_robot_mm`、`place_robot_mm` 和
`rotation_robot_deg`，不要用原始图像像素直接控制机构。输出顶层
`robot_calibrated=false` 时，这三项仍只是未标定诊断值，禁止据此驱动机构。

当前 UART 协议在发送前按 `80 pulse/mm` 把内部机构毫米坐标转换为回零后的绝对脉冲：

```json
{
  "piece_id": 0,
  "pickup_x_pulse": 9600,
  "pickup_y_pulse": 7200,
  "place_x_pulse": 18000,
  "place_y_pulse": 12800,
  "rotation_deg": 30.0
}
```

X 正方向从左向右，范围 `0..24000 pulse`；Y 正方向从上向下，范围
`0..16700 pulse`。四个 XY 字段都是绝对目标位置，不是从当前位置开始的相对运动量。
越界命令会在 UART 发送前被拒绝。旋转轴脉冲当量尚未确定，因此仍发送相对旋转角度。
UART 字段 `rotation_deg` 使用 `[0,360)` 内的顺时针角，`0` 表示无需旋转。

## MaixCAM2 运行

1. 先在设备设置中安装与系统匹配的最新 Runtime。
2. 用 MaixVision 打开整个 `maixcam2_puzzle_vision` 文件夹，必须选择“运行项目”，不能只
   运行 `main.py`，否则子模块不会上传。
3. 把 `config.example.json` 复制为 `config.json`，再按设备修改。`expected_piece_count=0` 接受现场的 1–4 片；
   已知固定为四片时可设为 `4`，能更早发现漏分割。默认使用
   `"solver_mode": "auto"`：先尝试固定图 2 的 48 次模板指派，形状不匹配时自动进入
   通用枚举。只有明确只测题图固定切法时才使用 `"figure2"`。
   `"texture_enabled": true` 会自动区分纯色片和扑克牌：纯色片跳过纹理评分，
   只有检测到牌面印刷图案时才比较接缝纹理。首轮通用搜索默认最多运行
   `15000 ms`；失败或只得到 `SEARCH_LIMIT` 候选时，恢复轮使用剩余预算，两轮求解合计不超过
   `30000 ms`。节点上限同时有效。
4. 默认保持 `"start_mode": "touch"`：`START` 拍摄并求解一轮，结果会一直保留；
   `STOP` 停止并丢弃本轮结果，`RESET` 清除本轮结果并恢复预览。`"immediate"` 仅用于上电自动
   求解一次；`"func_key"` 只作为旧硬件兼容项保留，正常使用不再需要 FUNC 键。
5. 需要给运动主控发送结果时启用 UART。当前硬件使用左侧 2.54 mm 排针的
   `U2T/U2R`，对应 B0/B1 的 UART2、`/dev/ttyS2` 和 3.3 V 电平；
   TX/RX 交叉并共地。当前 `config.json` 已写入本机 A4 四角标定并启用 UART；
   更换相机位置、分辨率、工作平面或坐标原点后，必须重新标定并先关闭真实运动。
   只验证接线和主控解析时，先关闭电机驱动并运行
   `tools/uart_smoke_test.py`；它发送 `status=UART_TEST` 的固定 JSON，
   不需要伪造机构标定状态。
6. 通过 MaixVision“安装应用”离线部署，或在项目目录运行 `maixtool release`。
   若要求上电后只按一次测试键，还要在设备“设置 → 开机启动”中选择本应用。正式测试前
   关闭 Wi-Fi，并确认断开电脑后可以独立运行。

板载相机由 `maix.camera.Camera` 取帧，再由 `image.image2cv` 转成 OpenCV BGR 数组。
不要把板载 MIPI 摄像头改成 PC 写法 `cv2.VideoCapture(0)`。

启动后终端应先出现类似
`[vision] config solver=auto, texture=on, pieces=auto, limit=15000 ms/attempt, 30000 ms total`。
固定图 2 在“solving puzzle...”之后还应立即出现
`[vision] trying bounded Figure-2 template solver`；其他切法随后会提示模板不匹配并
自动切换到 `generic C1/C2 mating solver`。缺少这些行说明板上仍是旧文件；
请停止运行并重新“运行项目/安装应用”整个文件夹，不能只发送 `main.py`。

## 建议的纸张和相机条件

- A4 必须是无纹理、哑光、纯色纸；建议选与白色现场片和自备片均有明显色差的中深色。
- 承载平台也应与 A4 颜色形成明显边界，但不能加入图案、角点或定位标记。
- 完整四条 A4 边和分界线必须在画面内；相机尽量正对纸面，焦点锁在纸面。
- 当前默认以 `1280×720` 取帧、以 `3 px/mm` 校正为 `630×891`。
- 相机帧率使用 MaixCAM2 官方模式中的 `30 fps`。
- 分界线可以不是黑色；代码按相对纸面 Lab 色差寻找贯穿纸宽的中部线。
- 现场碎片可能同形异纹，因此扑克牌配置不要关闭纹理评分；若自备纯色片之间本来就允许
  颜色跳变，则应关闭，否则“颜色连续性”会成为错误先验。
- `assembly.search_complete=true` 才表示有限候选集已经搜索完；触及节点/候选上限会返回
  `SEARCH_LIMIT`，不会冒充唯一解。
- `assembly.side_coverage_min`、`convexity_ratio` 和 `corner_error_max_mm` 是严格矩形资格指标；
  默认分别要求 `>=0.88`、`>=0.96`、`<=5 mm`。不要只看 `fill_ratio`。
- `paper_border_exclusion_mm` 和 `divider_exclusion_mm` 只用于背景/阈值估计，不再把
  靠近纸边或中线的合法碎片直接判错；规则保证碎片本身仍完整位于取料半区。
- 两片同色碎片若无缝贴合，单幅顶视图可能与“一片完整碎片”完全相同，这是不可观测情况。
  已知片数的自备题务必配置准确片数并留出可见间隙；现场题若出现这种极端摆法，任何仅靠
  单帧轮廓的方案都不能保证恢复真实分界。

python tools/calibrate_camera.py "calibration/*.jpg" `
  --columns 9 --rows 6 --square-mm 20

## 固定相机到机构坐标标定

锁紧相机后，在工作平面记录至少四组（建议 8–12 组）去畸变画面像素和机构实测坐标。
标定点应覆盖整个 A4 工作范围：

先保存一张与正式运行分辨率、方向完全相同的原始相机图，然后在电脑上运行点选工具：

```powershell
python tools/collect_calibration_points.py calibration_frame.jpg `
  --config config.json `
  --output calibration_points.json
```

建议先给标定纸上的十字编号，并按编号顺序点选。在窗口中左键依次点击十字中心；右键、
退格键或 `Z` 撤销，至少点四个点后按
回车结束，`Esc` 取消。图片即使为了显示而缩小，工具也会自动换算回原图像素坐标。之后
按终端提示，为每个编号输入同一个物理点的机构 `Xmm Ymm`。

如果主控目前只有绝对脉冲位置，也可以让工具按脉冲当量换算毫米。例如 X/Y 分别为
80 和 100 pulse/mm，回零脉冲均为 0：

```powershell
python tools/collect_calibration_points.py calibration_frame.jpg `
  --config config.json `
  --x-pulses-per-mm 80 `
  --y-pulses-per-mm 100
```

轴正方向相反时追加 `--x-direction -1` 或 `--y-direction -1`；回零对应的计数不为零时使用
`--x-zero-pulse`、`--y-zero-pulse`。如果暂时只想取得像素坐标，可使用
`--pixels-only`，之后再手动补上数量和顺序完全一致的 `robot_mm`。

输入完成后会直接生成如下格式：

```json
{
  "frame_px": [[420, 80], [850, 90], [900, 680], [360, 670]],
  "robot_mm": [[...], [...], [...], [...]]
}
```

然后执行：

```powershell
python tools/fit_frame_to_robot.py calibration_points.json
```

把输出的 `frame_to_robot` 复制到 `config.json`，复测通过后才把
`robot_calibrated` 改成 `true`。建议用未参与拟合的点做复测，整张 A4 范围内误差应显著
小于机械系统允许误差。标定照片若启用了镜头内参矫正，像素点也必须取自矫正后的画面。
如果输入的是已经去畸变并保存的图片，点选工具不要再传 `--config`，避免重复去畸变。
程序会在“启用 UART 但未声明完成标定”时拒绝启动，防止把画面像素误当成机构毫米坐标。

## 现场必须实测的参数

合成测试不能代替 MaixCAM2 实拍。拿到相机后至少采集：

- 自备纯色片 20 组随机位置和旋转；
- 现场同材质白片或自制镀锌薄铁片 20 组；
- 多张不同扑克牌、不同切法和同形异纹样本；
- 实验室不同灯位、曝光和轻微阴影；
- 上下半区不同阴影和分界线附近的亮暗带；
- 碎片靠近纸边、分界线，以及彼此间隔 `0.5–3 mm` 的边界情况。

记录分割片数、顶点毫米误差、拼接拓扑、旋转误差、运行时间和失败帧。若实际纸色、镜头、
安装高度或曝光改变，应先用这些回放帧调整 `config.json`，不要在求解器里散加特殊判断。

## 与运动主控的边界

本项目到 UART JSON 运动计划为止，是视觉协处理器代码，不包含电机闭环。运动主控还应：

1. 对整帧 JSON 做缓存后再解析，不能收到半包就动作；
2. 对每片执行吸取、旋转、放置并返回 ACK，失败时在两分钟内自动重试；
3. 全部执行后复核机构状态，再触发题目要求的声音或灯光提示。

`status=LOW_MARGIN`、`SEARCH_LIMIT` 或 `ERROR` 时板端不会通过 UART 下发动作列表。
